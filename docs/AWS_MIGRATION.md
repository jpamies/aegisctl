> Best-effort mapping of AWS services to Azure equivalents, generated by

## ⚠️ Disclaimer

This mapping is **best-effort and advisory**. Service parity between AWS and
Azure is not always 1:1. Each mapping should be validated by the engineering
team before adoption. Aegis does not guarantee functional equivalence.

## Confidence levels

| Level | Meaning |
|---|---|
| **High** | Direct equivalent exists; migration path well-documented. |
| **Medium** | Equivalent exists but with notable differences; code changes likely. |
| **Low** | No direct equivalent; significant rearchitecture needed. |

---

## Migration checklist

- [ ] Identify all AWS services in use (from repo analysis + infra).
- [ ] Map each service using the table above.
- [ ] Flag services with Medium/Low confidence for deeper review.
- [ ] Estimate code change effort for each service migration.
- [ ] Update IaC from CloudFormation/Terraform to Bicep.
- [ ] Update CI/CD pipelines to GitHub Actions targeting Azure.
- [ ] Re-implement secrets management (Managed Identity → Key Vault).
- [ ] Update monitoring/alerting to Azure Monitor + Application Insights.
- [ ] Plan data migration strategy (databases, storage, queues).
- [ ] Execute in phases: non-production first, then production with rollback plan.
